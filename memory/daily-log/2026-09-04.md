## Ambry (pantry) — sign-out regression, PR #181

**Branch** `fix/sign-out-regression-2026-09-04` → https://github.com/ezybg7/pantry/pull/181 (CI: checks/disclosures/gitleaks all pass; awaiting Everett).

**Root cause.** Sign out did nothing visible because two bare `await`s on network round trips sit in front of the state change, with the Profile screen's `router.replace('/welcome')` behind both: `retirePush`'s Data-API write in `src/features/auth/context.tsx` (bounded by `DB_TIMEOUT_MS` 12s, longer if the JWT mint stalls) and `this.post('/sign-out')` in `AuthClient.signOut` (**no fetch in `src/lib/authClient.ts` has a timeout at all** — bounded only by NSURLSession). Neither answer is read.

**Fix.** Retire runs against `RETIRE_GRACE_MS` (2s) and is otherwise left to the owed-retire marker; the revocation POST is sent, not awaited. Spec 16's guarantee holds: the `retiringUser` latch is synchronous, and a losing write is remembered as owed and flushed at the account's next sign-in.

**Open items.**
- The "jumps to the Add tab" half is NOT reproduced and not fixed by name. There is no automatic navigation to `/add` anywhere in `src/` — every one is behind a press. Needs a device re-check on this branch.
- `src/lib/authClient.ts` has no fetch timeouts — sign-in and every JWT re-mint can still hang for the platform default, and `mintFromSession` loops cookie strategies so one `accessToken()` can be four untimed requests. Deliberately out of scope; deserves its own PR.

**Test-harness fact worth remembering:** `renderRouter` from `expo-router/testing-library` calls `jest.useFakeTimers()` internally, so the usual `await act(() => new Promise(r => setImmediate(r)))` flush hangs forever. Drive it with `await act(async () => { await jest.advanceTimersByTimeAsync(ms) })`, several passes, and `jest.useRealTimers()` in `afterEach`. This is what stalled the previous agent's attempt.
