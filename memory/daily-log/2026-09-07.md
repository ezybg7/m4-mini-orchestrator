### GitHub Actions minutes blown — cause found, PR #206 (2026-09-07)

Everett hit the 3,000-minute monthly cap; CI has been failing account-wide since
05:23:16Z. His guess was "too many branches". Half right — the real cause is
**cost per run**, not run count.

**Measured** (685 runs since 09-01 = ~2,714 min = **90% of the cap in 7 days**):
CI 269 runs / **2,588 min** (avg 9.6, worst 49.4) — **95% of the entire bill**.
Everything else combined is 126 min (Secret scan 57, Disclosures 26, Dependabot
25, Pages 13, nightlies 5). All runners are `ubuntu-latest`, so it is NOT the
macOS 10× multiplier.

**Step timing, run 34086520882** (502 s green run): `npm test` **405 s = 81%**;
npm ci 31; lint 31; typecheck 14; workers 12; rest 9. Cause: `npm test` = jest +
a `posttest` (`scripts/test-timezones.mjs`) that re-runs the whole suite once per
pinned zone — **5 zones** (Honolulu, Chatham, Kiritimati, New York, Los Angeles),
so **six full passes of 4,324 tests on every push to every branch**. And no
`paths-ignore`, so prose-only PRs (my own #205 included) paid the same 8.4 min.

**PR #206** — three fixes: (1) zone sweep moves from every push to every merge —
PRs run `npx jest --ci` (one pass), `main` runs the full `npm test`; **502 s →
~164 s per PR run, −67%**. (2) `paths-ignore` for md/docs/specs/site/.claude/
.codex — fires only when EVERY changed file matches, so mixed PRs still run
fully; safe because main has **no branch protection**, so no required check can
be blocked. (3) `cache-dependency-path` for both lockfiles — `cache: npm` keyed
on the root only, so `npm --prefix workers ci` hit the network every run.
**Gotcha avoided: GitHub Actions does not expand YAML anchors** — the paths list
is duplicated verbatim under push and pull_request with a comment saying so.

**Stated tradeoff:** a TZ regression can now reach main before it is caught
(caught on the merge commit, same day; `expiry.test.ts` keeps its own zone
assertions).

**Durable fix offered, not done:** a **self-hosted runner on the M4 mini costs
zero Actions minutes** (GitHub meters only its own runners). The mini is up 24/7
with the full toolchain and pantry is private, which removes the untrusted-fork
risk. That would make the cap moot and let the zone sweep go back onto every PR.
Awaiting Everett's go-ahead; would be a launchd service beside the others.

### Self-hosted GitHub Actions runner on the mini — live (2026-09-07, PR #206)

Everett approved the runner. **Done and verified: CI is green, free, and 6.7× faster.**

- **Runner:** `m4-mini`, labels `self-hosted,macOS,ARM64,m4-mini`, registered to
  `ezybg7/pantry`. Install at `~/actions-runner` (v2.337.0, osx-arm64).
- **Service:** launchd `actions.runner.ezybg7-pantry.m4-mini`. `svc.sh install`
  writes RunAtLoad only — **I added `KeepAlive` + `ThrottleInterval 30`** via
  PlistBuddy to match `com.user.hermes` (without KeepAlive a crashed runner means
  every CI job queues silently forever).
- **CRITICAL GOTCHA:** a launchd agent does **not** source `~/.zshenv`, so the
  runner cannot find node/npm/git from Homebrew. Fixed with the runner's own
  **`.path`** file (`/opt/homebrew/bin:...`) plus `.env` for a UTF-8 locale.
- **`cache: npm` is HARMFUL on self-hosted.** First run was 358 s of which
  **274 s was `Post Run setup-node`** — uploading the npm tree to GitHub after the
  job. `~/.npm` persists locally between jobs (`npm ci` = 5 s warm). Removed it:
  **358 s → 75 s.** Restore lines kept in a comment for a hosted fallback.
- **GitHub Actions does not expand YAML anchors** — `paths-ignore` written out
  verbatim under both `push` and `pull_request`.

**Numbers:** hosted `ubuntu-latest` 502 s **billed** → self-hosted **75 s free**
(6.7×). Full six-pass suite: 405 s hosted vs **46 s** on the mini (M4 8-core vs
2-core runner). Because minutes are free, **the C12 timezone sweep went back onto
every PR** — no gate was traded away after all.

**BIG ONE: self-hosted jobs run even while the account is billing-blocked.**
Proven in the same push — CI succeeded on the mini while `Disclosures` and
`Secret scan` (still `ubuntu-latest`) failed on billing. So merging #206
