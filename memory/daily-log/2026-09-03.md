- **Task:** verify whether audit C12 (`specs/audit-2026-07-23.md`, "UTC date-only math can be a day off near midnight") is still true now that `profiles.timezone` shipped (migration 0044, spec 16), and fix it if so. - **Verdict: still true, and worse than "near midnight".** The client was UTC everywhere; the server digest had moved to `profiles.timezone` and the client never followed, so the two halves had been disagreeing since 0044. In Honolulu (UTC-10) the bad window is **14:00→midnight, ten hours of every day**: `expires_at` tomorrow rendered "today", today rendered "1d overdue" + red badge, the "+2 days" swipe gave three, a 7-day shelf life stored 8 days, and `RemindersProvider`'s plan started a day late — dropping a whole digest, because `scheduler.ts` has always fired plan dates at *local* 08:00 while "today" came from UTC. Auckland/Chatham = mirror image each morning.
- **Evidence (pre-fix):** `expiry.ts:52` (`getUTCFullYear` today), `:38` (`toISOString().slice(0,10)`), `:33` (`addedAt + days*86_400_000`), `:42`; consumers `UrgencyBadge.tsx:11-12`, `expiring.tsx:49,192`, `locationFilter.ts:38`, `outcomes.ts:163`, `hooks.ts:80,448`, `RemindersProvider.tsx:244`. **Second UTC implementation** at `matching.ts:55-61`, under a comment claiming it existed so the two "never disagree by a day". **Server confirmed already correct:** `workers/src/digest.ts:128-136` `to_char((now() at time zone tz.name)::date,…)` joined on `pg_timezone_names`, passed to `digestFor` as an explicit `local_date` — unchanged by this PR.
- **Fix:** one day notion in `expiry.ts` — `localDayStart` + `dayOrdinal` (both `Date.UTC(y,m,d)` *ordinals*, exact at half-hour offsets), local `toDateOnly`, new `addCalendarDays` (pure string arithmetic), `computeExpiresAt` counting with `setDate` so a 167-hour DST week can't spend a day. `digest.ts`'s `addDays` moved onto `addCalendarDays` — **load-bearing**: it used to anchor at UTC midnight, and anchoring at *local* midnight instead would have made phone and server bucket the same pantry differently. `matching.ts`'s twin deleted.
