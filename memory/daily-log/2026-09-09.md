## Apple HIG skill — full ingest and ruleset build

**What was done.** Read the entire Apple Human Interface Guidelines page by page
and built a persistent skill from it at `~/.claude/skills/apple-hig/`.

- Discovered the HIG is served as Swift-DocC render JSON at
  `developer.apple.com/tutorials/data/design/Human-Interface-Guidelines/<slug>.json`
  — complete structured content, no JS rendering or scraping needed.
- Crawled all **172 pages** (BFS from the root topicSections), wrote a lossless
  JSON→Markdown converter (0 unknown node types across the corpus), and extracted
  **2,347 guidance rules** (the HIG's semantic unit is the paragraph opening with a
  bold imperative sentence — those bold leads *are* the rules).
- Read in the order requested: design principles → designing for iOS → color,
  typography, layout, materials, accessibility, app icons → patterns → components →
  remaining foundations → inputs → technologies and other platforms last.
- Wrote 17 reference files (~5,100 lines) plus a `SKILL.md` ruleset.

**Decisions.**
- Split into `SKILL.md` (applied from memory: principles, hard numbers,
  component-choice tables, anti-patterns, review checklist) + `references/`
  (progressive disclosure, loaded on demand). Kept Apple's bold-lead phrasing
  nearly verbatim rather than paraphrasing — the specificity is the value.
- Built `tools/check.py`, a lexical coverage checker that flags source rules whose
  vocabulary is absent from the references. Ran it after every topic; it caught
  real gaps (visionOS typography rules, 4 drag-and-drop rules, tvOS title cards,
  ML attributions/limitations, AR relocalization/badges, the three visionOS
  immersion styles) that I'd otherwise have missed. ~15% false-positive rate —
  every flag was verified by hand.
- Verified every numeric constant in SKILL.md directly against source text.
- Saved the crawler + checker into `tools/` so the skill can be regenerated when
  Apple updates the HIG.

**Notable content facts** (post-dating older HIG knowledge):
- The **eight design principles** (Purpose, Agency, Responsibility, Familiarity,
  Flexibility, Simplicity, Craft, Delight) were **reintroduced June 8, 2026**.
- **Liquid Glass** is the current design language: a functional layer above content,
  regular vs clear variants, never in the content layer (except transient slider and
  toggle states).
- Control sizes are now given as **default vs minimum** per platform, not a single
  number (iOS 44×44 default / 28×28 minimum).

**Open items.** None blocking. The skill is registered and loads. Re-run
`tools/crawl.py` after Apple's next HIG update (change logs are per-page).

### Verification pass on the HIG skill

Re-audited the skill with stricter methods after realizing the first checker was
too permissive: it matched each rule's vocabulary against the **whole** references
directory, so a rule could appear covered by coincidental overlap from an unrelated
file. Rebuilt verification as four escalating checks (`check.py` → `check2.py` →
`verify.py` → `gaps.py`, all now in `tools/`), mapping every page to the single
reference file that should contain it.

That surfaced real gaps the first pass had missed — whole subsections, not stray
rules: the visionOS **Best practices** section, machine learning's
confidence/options/corrections guidance, AR reference images and badging, visionOS
**spatial widgets** (paper/glass/mounting styles) and widget placements (StandBy,
Always-On, Smart Stack), macOS drag-and-drop, watchOS button layout, tvOS/watchOS
video and audio rules, and chart description guidance. All fixed.

Final verified state: core principles **33/33** statements captured, all 8
principles and taglines present in both layers; SKILL.md **24/24** semantic claims
traced to references and every numeric constant checked against source; `gaps.py`
reports **0** zero-match gaps; hand audit of a random 25 of the 200 remaining
lexical flags found 24 already present → **~99.6% corpus coverage**.

Lesson worth keeping: lexical coverage checks need to be scoped per-file and
confirmed by hand — and multi-word greps silently miss line-wrapped text, which
produced several false "gaps" during this audit.
