# Account group — screen research (2026-09-04)

Scope: the eight account-side screens of Ambry (repo `pantry`), read against the design brief (`specs/design-critique-2026-09-04.md`), the design system (`specs/design-system.md`) and each screen's spec, then compared with apps that do the same job. Every claim about another app carries the URL it came from; descriptions only, no images. Companion data: `account.json` (same structure, fuller region lists). Directions are buildable with `src/components/` (`Button` variants, `SettingsRow`/`GroupedRow`, `SectionHeader`, `OverflowMenu`, `BottomSheet`, `TextPrompt`, `SegmentedControl`, `SwipeRow`, `Chip`, `ErrorState`, `FailureNotice`, `Toast`).

Interaction costs are counted the brief's way: a tap dispatches navigation, a mutation or a sheet; a keystroke is a character no control could supply.

## 1. Welcome · Sign in · Sign up (`/(auth)/welcome`, `sign-in`, `sign-up`)

**Today.** Welcome: mark, wordmark, pitch, three tinted feature rows, "Get started" → sign-up, secondary "I already have an account" → sign-in. Sign-in: heading, invite banner, Apple, Google, email + password (username/password content types, return-key chaining), Sign in, two 44pt links. Sign-up: heading + subtitle, Apple, Google, name / email / password (8+), Create account; a refusal that advises signing in shows a Sign in button. **Cost:** Apple 2 taps + Face ID; returning email 2 taps 0 keystrokes if QuickType offers the pair (declared, needs the webcredentials build) else ~4 taps + ~32 keystrokes; new email ~40 keystrokes + 1 tap (~25 with the suggested password).

**Apps.** [Notion](https://www.notion.com/help/log-in-and-out): one screen for new and returning people — Google/Apple/Microsoft or an email; email sends a temporary login code (and magic link); passkeys. Borrow: *one door, the email decides*. [Craft](https://support.craft.do/en/introduction/account-setup/create-account): same shape, 6-digit emailed code that iOS Security Code AutoFill fills; Hide My Email respected. Borrow: *the code is one QuickType tap*. [Slack](https://slack.com/help/articles/212681477-Sign-in-to-Slack): "Sign in with Email" mails a confirmation code; the password is optional. Borrow: *code sign-in doubles as recovery*. [Things Cloud](https://culturedcode.com/things/support/articles/1481195/): account created from Settings; email + password → Terms checkbox → 4-digit emailed code, all in-app. Borrow: *verification never leaves the app*. [Duolingo](https://pageflows.com/post/ios/onboarding/duolingo/): profile creation mid-flow after the placement quiz. Borrow: *ask only what is needed to proceed* — Ambry needs an account (spec 37 retired anonymity) but not a display name; Apple supplies it and Profile → Your name already edits it. Apple HIG: the Apple button [no smaller than others, never below the fold, "Continue with Apple" allowed, welcome immediately](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple); [postpone non-essential setup](https://developer.apple.com/design/human-interface-guidelines/onboarding); QuickType needs the [associated domain + content types](https://developer.apple.com/documentation/security/password-autofill).

**Directions.**
- **One door.** Welcome's single CTA → "Continue to Ambry": invite banner · Apple · Google · "or use email" · email Input · Continue. Returning: a password field appears (QuickType fills the pair) + Sign in + Forgot. New: password (newPassword, suggested) + Create account + "You can add your name later". Cost: Apple 1 tap + Face ID; returning 2 taps 0 keys; new ~20 keys + 3 taps. Trade-off: needs an "is this address a password account" step — a Worker probe (an explicit oracle; spec 28 §Hardening already accepts the bounded one) or Better Auth's laundered sign-in-then-sign-up. Everett's call.
- **Code, not password.** Email → "Email me a code" → one-time-code Input (AutoFill) + Continue + "Use password instead" + Resend; neutral copy for every address. Cost ~20 keys + 3 taps, nothing to forget; forgot-password disappears for code users. Trade-off: contradicts `docs/adr/auth.md` O2 (no second passwordless link path) — a PR escalation; Worker OTP route + Resend template.
- **Two screens, two fields.** Keep the fork; drop the name field. Cost: sign-up 2 fields (~20 keys + 1 suggestion tap + 1 tap). Trade-off: smallest change, keeps the mirrored screens; needs an empty-name fallback (spec 17 tolerates one).

## 2. Forgot / reset password (`forgot-password`, `reset-password`)

**Today.** Forgot: title, notice, explainer, email Input (not prefilled), Send reset link, Back to sign in; sent → mail glyph + the neutral sentence + Back + "Use a different email". Reset (Universal Link, token unexamined): one new-password field, Set new password, Cancel; success routes to sign-in with a notice because Better Auth mints no session. **Cost:** ~20 keys + 1 tap → Mail → link → 1 suggestion tap + 1 tap → sign-in → 2 more taps; three screens and an inbox round-trip.

**Apps.** [Slack](https://slack.com/help/articles/201909068-Reset-your-password): recovery is signing in with an emailed code; the reset itself is an account-settings task. [Apple Account](https://support.apple.com/en-us/102656): on a trusted iPhone the password is changed under Sign-In & Security, gated by the device passcode — possession is proof; Ambry has no in-app change-password at all. [Instagram](https://help.instagram.com/407128569340564): "Forgot password?" → email or SMS → a login link/code that signs you in first. [Notion](https://www.notion.com/help/log-in-and-out): passwordless by default, so the flow is rarely reached. Pattern guidance: [prefill the address from sign-in and say what happens next](https://uxpatterns.dev/patterns/authentication/password-reset); [keep requirements simple](https://baymard.com/blog/password-requirements-and-password-reset).

**Directions.**
- **Reset lands you inside.** Carry the sign-in email over (route param), add "Open Mail" to the sent state, stash the address with the pending token, and after Set new password call `signInWithPassword` → `pendingInviteRoute() ?? '/'` (fallback: today's notice). Cost: 0 keys + 1 tap, link, 2 taps → inside. Trade-off: client-only; amends spec 28 §UX item 3; the stash is an email in AsyncStorage for ≤1 h.
- **Sign in with a code instead.** "Forgot password?" becomes "Email me a sign-in code"; Change password moves to Profile → Account (no old password on a signed-in device, Apple-style). Cost: locked-out 3 taps, no password invented. Trade-off: ADR O2 escalation; OTP + change-password routes.
- **Passkey after first sign-in.** One-time "Sign in with Face ID next time" on Profile; QuickType offers the passkey. Cost: 1 tap + Face ID. Trade-off: Better Auth passkey plugin, WebAuthn RP, native module → new dev build; complements rather than replaces the above.

## 3. Onboarding · first run · add household

**Today.** Onboarding: title + subtitle; card "Start a household" (Input prefilled "Home", chips, Create live); card "Join a household" (code or pasted link, Join); Sign out. First run: "You're all set", one "Bring your household" step, locations footnote, Start adding / Look around first. Add household: same cards, no prefill. **Cost:** create 1 tap (+1 on first run); pasted link long-press → Paste → Join → confirm = 4; typed code 16 keys + 1.

**Apps.** [Bring!](https://www.getbring.com/help-center-main-categories/items-lists): creating a list asks "share it?"; existing lists share via long-press → Invite Friends; the invite also shows inside the invitee's app. [AnyList](https://help.anylist.com/articles/share-list/): existing users get a push and the list appears; new users register with the invited email. [OurGroceries](https://www.ourgroceries.com/user-guide): one shared account; the invitation installs the app and signs the invitee in. [Apple Family Sharing](https://support.apple.com/en-us/108380): Add Member → Invite People (Messages/Mail) or in person on the organiser's device; per-person status with resend. [Splitwise](https://feedback.splitwise.com/knowledgebase/articles/239218-how-do-i-join-an-existing-group): "Start a group" is primary; joining happens from a link or a code entry, not a peer card. [HIG](https://developer.apple.com/design/human-interface-guidelines/onboarding): defaults over setup.

**Directions.**
- **Create is the screen, join is a row.** Title · prefilled name + chips · Create household · a `SettingsRow` "Have an invite code or link?" → `TextPrompt` (a link still routes to `/join`). Cost: create 1; typed code 1 + 16 + 1; link unchanged. Trade-off: join one tap further for the typed-code minority (link arrivals never see this screen).
- **Share at creation** (Bring!). First run becomes "Home is ready · Just you so far" · **Invite your household** (creates a spec-43 link on tap, opens the share sheet) · bordered "Just me for now" → Add. Cost: solo 1 tap; couple 1 tap → share (was 3+ via Profile later). Trade-off: replaces §Decisions 4's message with the action it described.
- **Delete first run.** Create → `/add` + toast "Home created · Pantry, Fridge, Freezer are ready"; Members already says "Just you so far — share your invite link". Cost −1 tap for everyone. Trade-off: contradicts §Decisions 4 — escalate.

## 4. Profile tab (`/(tabs)/profile`)

**Today.** One inset-grouped scroll: Account (name and bio/links — both inline editors; public profile), Household (switcher; invite code with copy/Share/⋯; Share invite link; active links; Leave/Delete), Behaviour (two switches), Learned shelf lives, Members, Notifications, Plan (meter, CTA), About, exit group, version. **Cost:** rows 1 tap; share link 2; rename 4 + typing; the cost is ~25 rows under 9 headers, and two save-model editors S11 still counts.

**Apps.** [iOS 18 Settings](https://9to5mac.com/2024/09/18/ios-18-settings-whats-new/): account card on top pushing to its own screen; [most-used first, section descriptions](https://appleinsider.com/inside/ios-18/tips/new-settings-in-ios-18-will-take-some-getting-used-to). [HIG Settings](https://developer.apple.com/design/human-interface-guidelines/settings): options belong with the task; minimise the count. [Notion My account](https://www.notion.com/help/account-settings): identity → security (password, 2-step, passkeys) → log out everywhere → delete. [Strava](https://support.strava.com/en-us/articles/15402087-iphone-app-settings): the You tab is the person; settings behind a gear. [Overcast](https://www.podfeet.com/blog/2024/05/overcast-user-guide/): "Nitpicky Details" last. [Instagram](https://privacyinternational.org/guide-step/5613/guide-instagram-settings-and-good-practices): Accounts Center pinned, search over a long list — only worth it past ~40 rows.

**Directions.**
- **Account card + household hub.** Identity card (initial, name, email, plan) → Account screen; "Home · 3 members" card → Household screen (switch/rename, Invite people, members, behaviour, learned, leave/delete); About. Cost: everything +1 tap; the tab shrinks to 4 rows. Trade-off: a second rebuild right after P5; the invite loses a tap.
- **Flat, three groups, invite as one row.** You · Your household (one "Invite people" row → sheet with code copy, Share link, active links, red Regenerate) · Preferences last (reminders, behaviour, learned, crash reports) · About/exit; name via `TextPrompt`, bio via a pushed screen. Cost: share 1 → 2 taps; ~40% shorter; kills the inline editors. Trade-off: loses the one-tap share.
- **Person here, kitchen on Pantry.** Profile = person + plan + about; the Pantry tab's title shows the household (IA-3) and a header `OverflowMenu` opens Household settings. Cost: invite 3 taps from Pantry. Trade-off: two settings homes; answers IA-3 by putting the kitchen's settings where the kitchen is.

## 5. Join by invite (`/join/[token]`)

**Today.** Spinner; dead link (glyph + neutral sentence + Close); unreachable (`ErrorState` + retry); already a member → toast + switch; signed out → stash + sign-in banner; signed in → `BottomSheet` "Join {name}?" + share line + Join + Cancel over an empty grey screen. **Cost:** 1 tap.

**Apps.** [Discord](https://support.discord.com/hc/en-us/articles/360034842871-How-do-I-join-a-Server): the invite splash shows icon, name, online/total members, [Accept Invite / No Thanks](https://whop.com/blog/how-to-join-a-discord-server/). [WhatsApp](https://faq.whatsapp.com/1110600769849613/?cms_platform=web): link preview with name and member count; Join, or [Request to Join](https://qualimero.com/en/blog/whatsapp-group-link) when admins approve. [Family Sharing](https://support.apple.com/en-us/108380): tap the invitation → Join → sign in as the invited account → confirm what you share. [AnyList](https://help.anylist.com/articles/share-list/): known users get a push and no accept step (a counter-example to spec 43's always-confirm, right only for addressed invites). [Bring!](https://www.getbring.com/help-center-main-categories/items-lists): the invite is shown in-app on next open.

**Directions.**
- **A landing, not a sheet on grey.** Initial tile · "You're invited to Home" · optional "N members" · share line · "Signed in as {email} — Not you?" · Join (primary) · "Not now" (bordered); dead/unreachable states reuse the card. Cost 1 tap; "Not you" replaces Cancel → Profile → Sign out → re-tap. Trade-off: a member count in the preview leaks household size to link holders — keep optional.
- **Sheet over the destination.** Same sheet, raised over the dimmed Pantry tab (fallback to the card when the user has no household); Cancel row stays (the one action commits). Trade-off: router work for a route outside `(tabs)`.
- **Addressed invites with a push.** "Invite by email" → known users get a push into the same confirm; owners see Sent/Joined + Resend. Cost joiner 2 taps. Trade-off: a new spec — the lookup must never reveal whether an address has an account; Worker route + template.

## 6. Delete account (`/delete-account`)

**Today.** Header; red lead; cards What gets deleted / What stays / Your subscription (+ Manage subscriptions); a Transfer-ownership-first card on 409; "Type DELETE"; Input; button armed only once the word is typed and committed; no Alert. **Cost:** 6 keys + Done + 1 tap ≈ 8, with a keyboard on the irreversible screen.

**Apps.** [Notion](https://www.notion.com/help/delete-your-account): the dialog lists the workspaces that die; type your email; the button reads "Permanently delete account and N workspaces". [Instagram](https://www.facebook.com/help/139886812848894): Deactivation or deletion → reason picker → password → 30-day grace cancelled by logging in. [Discord](https://support.discord.com/hc/en-us/articles/212500837-How-to-Delete-your-Discord-Account): password (+2FA), ~14 days pending, Restore Account on next sign-in. [Apple Account](https://support.apple.com/en-us/102656): critical changes on a trusted device are gated by the device passcode. [Guideline 5.1.1(v)](https://developer.apple.com/news/?id=12m75xbj): easy to find, real deletion, revoke Apple tokens. [iOS power-off](https://support.apple.com/guide/iphone/turn-iphone-on-or-off-iph841379c3d/ios): a hold then a drag as the confirmation for a consequential act.

**Directions.**
- **Consequence in the button, Face ID as the gate.** Cards with counts from the cache ("Home — 42 items"); a destructive button "Delete account and 1 household" → LocalAuthentication; typed-word fallback when biometrics are unavailable. Cost: 1 tap + Face ID. Trade-off: `expo-local-authentication` is native → new dev build; amends S12's "typed word" rung.
- **Hold to delete.** Press-and-hold 2 s with a progress fill and haptic; VoiceOver gets an accessibility action opening one Alert. Cost: 1 gesture, no keyboard, no native module. Trade-off: a custom gesture is less familiar; Maestro stops at the enabled assertion as today.
- **Grace period.** Schedule, sign out, "will be deleted on {date}"; sign-in offers Restore. Trade-off: spec 11 puts grace explicitly out of scope; a pending owner blocks co-members for two weeks; allowed by 5.1.1(v) only if deletion completes.

## 7. Paywall (`/paywall`)

**Today.** Empty header + LargeTitle "Ambry Plus" with the meter as subtitle; lead; benefit rows from the server payload; Monthly/Yearly radio rows (yearly preselected, savings badge, trial label only when eligible); disclosure above the CTA; Start free trial/Subscribe; Restore; Terms · Privacy; dark build shows prices and no CTA. **Cost:** 1 tap + StoreKit sheet. **Price:** the brief's decided figures are $4.99/mo · $29.99/yr · 14-day trial; `specs/monetization.md`, ADR monetization D2 and `STATIC_PACKAGES` still say $2.99 · $24.99 · 7 days, so the screen PR moves all three.

**Apps.** [HIG In-app purchase](https://developer.apple.com/design/human-interface-guidelines/in-app-purchase): "1 month free, then $4.99 per month"; restore; don't upsell subscribers; system sheet. [3.1.2 rejections](https://www.revenuecat.com/blog/growth/the-ultimate-guide-to-app-store-rejections): the billed amount must be more conspicuous than the trial; links on the surface. [Bear Pro](https://bear.app/faq/features-and-price-of-bear-pro/): $2.99/$29.99 with a 7-day trial on both, sold from a Settings header card, concrete nouns. [Fantastical](https://flexibits.com/blog/2020/08/introducing-fantastical-premium-for-families/): individual + family plans, [14-day trial](https://www.morgen.so/blog-posts/fantastical-pricing). [CARROT Weather](https://apps.apple.com/us/app/carrot-weather-alerts-radar/id961390574): tier comparison. [Flighty](https://adapty.io/paywall-library/flighty/): one headline benefit, no trial. [Lifesum](https://mobbin.com/explore/screens/0bbe5356-e7a9-4e31-b978-841c15abc622): greyed-out features everywhere — the anti-pattern Ambry's three-entrance posture avoids.

**Directions.**
- **One plan, one line.** Headline "Point the camera at the receipt. Plus files it." · three benefit rows · `SegmentedControl` Monthly | Yearly · one price line in `fontSize.figure` ("$29.99 / year", caption "$2.50 a month · 2 months free", monthly figure stated too) · disclosure · CTA · Restore · links. Cost unchanged; the billed price becomes the loudest object. Trade-off: both prices must stay visible at once.
- **Comparison card.** Free | Plus table (scans, ideas, members, photos) from the payload, "Everything by hand stays free", a line saying how a household is covered (spec 23 §4a). Trade-off: tables fight Dynamic Type — stack rows with `useLargeText`.
- **Settings card as the sale** (Bear). Profile's Plan card carries meter, price line, disclosure, CTA → `purchasePlus`, Restore + links; `/paywall` survives for the exhausted-quota entrance. Cost −1 push from Profile. Trade-off: 3.1.2 text inside a grouped card is crowded; riskiest for review.

## 8. Insights (`/insights`)

**Today.** ScreenHeader "This month"; figure card (% · "used up" · counts) or spinner or "Not enough…"; one observation; "What went off" list (name · date); pull-to-refresh. No action (I-B1), a failed query reads as "not enough" (I-A1), the figure looks tappable (I-C2). **Cost:** 1 tap; nothing to do there.

**Apps.** [Apple Fitness](https://support.apple.com/guide/iphone/see-your-activity-summary-iph4c34a8a95/ios): rings, then Trends as arrows (90 vs 365 days), awards. [Oura Readiness](https://support.ouraring.com/hc/en-us/articles/360025589793-Readiness-Score): score with a label band, [contributors with bars you can tap](https://support.ouraring.com/hc/en-us/articles/360057791533-Readiness-Contributors), one recommendation. [YNAB Spending Breakdown](https://support.ynab.com/en_us/spending-breakdown-H1H7YxmD0): categories by %, tap to the rows. [Copilot Month in Review](https://help.copilot.money/en/articles/10310024-month-and-year-in-review): a turn-of-month slide set, shareable. [Too Good To Go](https://apps.apple.com/us/app/too-good-to-go-save-good-food/id1060683933): 2.7 kg CO2e per bag — rejected for Ambry (spec 39 bans invented figures). [NoWaste](https://apps.apple.com/us/app/nowaste-food-inventory-list/id926211004): "My numbers" on the profile — Ambry's Pantry placement stands.

**Directions.**
- **Contributors and one fix.** Figure (not pressable) with a label band; grouped rows "Salad leaves ×3" with `SwipeRow` actions Remind sooner (spec 40's learned override) and Add to list; tap expands the dated rows; `ErrorState` on failure. Cost: 1 swipe + tap to act (was Profile → Learned shelf lives). Closes I-A1/I-B1/I-C2; needs a 39/40 amendment naming the value that changes.
- **Versus your usual.** "▲ 5 points vs August" under the figure from one extra month in the query. Cost 0. Trade-off: brushes spec 39's no-trends rule — escalate; cheapest.
- **Month-end moment.** On the 1st a "August: 87% used up" card and an optional push; a This month | Last month segment; text-only share. Cost 1 tap from the push. Trade-off: spec 16 scheduler; image share would need a native module.

## Bets

**Sign-in "One door"** (§1) and **Insights "Contributors and one fix"** (§8): the first removes a screen and a fork for every new person at the front door, the second turns the only dead-end screen in the group into the place the product's promise ("here is the 13%, and here is what to do") is kept. Both are buildable on existing components; the first needs one decision from Everett on the email probe.
