# Add & capture — screen research, 2026-09-04

_Group "add-capture". Read against `main` at `dfcd0f0` (after design packages P1–P7). Principles: minimal interactions · no keyboard where a control will do · no duplicated headers · iOS grouped-list feel · Android-clean. Every direction is buildable with `src/components/` and keeps camera work inside `expo-camera` / `expo-image-picker`. Mobbin, Page Flows and Screens Design are login/JS-only — no usable text this session; sources are help centres, docs, store listings and walkthroughs. Constraints respected: ADR `capture-vision` **D3** (a human review before any write; a deliberate gesture after a preview before quota is spent) and **D4** (charge on success). Where a direction strains D3 it says so._

## 1. Add tab — `src/app/(tabs)/add.tsx` (+ `SearchCapture.tsx`, `ConfirmSheet.tsx`)

**Today.** Large title → basket bar ("N items staged · Review", only when staged) → `SearchField` "Search for a food" → results as grouped rows (category tile · name · "Fridge · ~7 days" · trailing **+** = one-tap add with a toast carrying **Change**; the row body opens the sheet) plus "Add “x” as new item" → **Scan barcode** / **Snap groceries or receipt** rows → **RECENT** (5, each with +) → confirm sheet (Cancel · item card · Leftovers chip for free text · Location segmented ≤4 else picker · Expires + once-only explainer · **Add to Fridge**). **Cost:** catalog food = keyboard + 1 tap (+) or 2 (row → Add); Recent re-buy = 1 tap but below the camera rows; free text = keyboard + 2.

**Apps.**
- **AnyList** — one field; suggestions from the built-in database, favorites and recents, each with a source icon; **tap adds, the pencil edits first**; Favorites and Recent are browsable lists. _Borrow:_ add-by-default with detail opt-in; Favorites distinct from Recent. https://help.anylist.com/articles/feature-overview-adding-items/
- **Bring!** — bottom field; a **tile catalog by category** browsed without typing; a green **Recently used** strip; long-press for quantity. _Borrow:_ browse-by-category as a keyboard-free path; recents as a strip. https://www.getbring.com/help-center-main-categories/items-lists · https://www.makeuseof.com/organize-family-shopping-with-bring-grocery-app/
- **MyFitnessPal** — before typing, **Recent / Frequent / My foods** under the search bar; the barcode button sits beneath the field. _Borrow:_ Frequent as a view (Ambry's Recent is recency-only). https://community.myfitnesspal.com/en/discussion/10843437/when-logging-food-how-to-search-only-foods-you-039-ve-already-logged
- **Apple Reminders (Groceries)** — items auto-file into sections; drag to another section and the list **remembers the preference for that item**. _Borrow:_ a remembered shelf correction per food. https://support.apple.com/en-us/105086
- **Instacart** — a **Buy it again** badge on search results, a carousel on home, + on the tile. _Borrow:_ mark results already bought so search and Recent are one list. https://docs.instacart.com/storefront/learn_about_your_storefront/shopping/buy_it_again/

**Directions.**

**1A — Recents up front.** _Pitch:_ the tab's own claim ("most adds are a name you already know") is undone by putting Recent under the camera rows. _Regions:_ title · basket bar · SearchField · **Frequent strip** — 6–8 tile+name chips, tap adds (toast/Change), long-press opens the sheet (Bring!, MFP Frequent) · results replace all of it while typing · Scan / Snap rows. Empty: no strip until 3 adds. _Cost:_ re-buy 1 tap, no scroll. _Trade-off:_ a horizontal strip is a second list idiom on a screen that just lost one (S3); long-press is undiscoverable, so Change must also reach the sheet.

**1B — Browse, don't type.** _Pitch:_ 421 curated rows are already cached (`useCatalogIndex`); a category grid reaches any staple with no keyboard. _Regions:_ title · basket bar · SearchField · Recent (5 rows) · **grid of the 12 `CategoryTile`s** · Scan / Snap rows · a tile pushes "Produce": grouped catalog rows with subtitle and + (row → sheet); search stays on top. Empty: never; a category with no visible rows is hidden. _Cost:_ staple = 2 taps, zero keyboard. _Trade-off:_ scrolling 40 rows beats two letters only for a new household — a discoverability win, not a speed win; the camera rows sink unless the grid is one row.

**1C — Tap adds, pencil edits.** _Pitch:_ a result row still has two affordances doing different things; make the row the add (AnyList). _Regions:_ as today, but the row commits with the suggested defaults and a toast with **Change**; the trailing glyph becomes a pencil that opens the sheet first; the free-text row keeps the sheet. _Cost:_ any catalog food = keyboard + 1 tap; edit-first = 2. _Trade-off:_ Change cannot move a row (`merge_add_items` returns no ids, spec 32 §Follow-ups), so a wrong shelf is a second copy — honest only after the RPC returns what it wrote (migration, escalation); strains D3's "type-ahead → confirm card" beyond A7.

## 2. Barcode scan — `src/app/capture/scan.tsx` (+ `ScanCapture.tsx`, `scanGate.ts`, `useBarcodeLookup.ts`)

**Today.** ScreenHeader "Scan barcode" → camera card (reticle, hint, torch) → **Enter number instead** (reveals digits + Look up) → scan bar ("N staged" · **Review**). Detect → haptic → Worker lookup (catalog → OFF → not found) → success haptic + live count; toast only for unknown, duplicate or error (**Add by name**). The basket survives leaving; the denied card keeps the digits field and Review. **Cost:** 0 taps per product; a session ends in 2 (Review → Add N); an unknown barcode is named later in the editor (open + type + dismiss).

**Apps.**
- **Yuka** — camera stays live; the colour verdict appears at once as a card, tap for the sheet. _Borrow:_ result-as-card, feedback with content. https://help.yuka.io/l/en/article/it3abac47h-how-scan
- **MyFitnessPal Multi-Add** — keeps the session open after the first scan; each scan lands in a temporary list; log all at once; not-found prompts you to create the food. _Borrow:_ the staged list visible while scanning. https://eathealthy365.com/myfitnesspal-barcode-scanner-your-ultimate-how-to-guide/
- **Pantry Check** — scanner is the default pane; **scanned items queue at the bottom of the scanner**; swipe right for name lookup; **Add to Inventory** commits the queue. _Borrow:_ queue under the viewfinder, commit from the scanner. https://pantrycheck.com/kb/add-items-screen/
- **Sortly Quick Actions** — choose the action first (adjust, move to folder, tag); every scan applies it; swipe between saved actions at the bottom. _Borrow:_ set the destination first, then scan. https://help.sortly.com/hc/en-us/articles/360012367432-Quick-Actions-on-the-Sortly-Mobile-App
- **Barcode Buddy (Grocy)** — Purchase/Consume modes; unknown codes parked under **New Barcodes** to associate later. _Borrow:_ unknowns never stop the haul (Ambry already does this — keep). https://barcodebuddy-documentation.readthedocs.io/en/latest/usage.html
- **Apple Camera** — passive detection and a tappable badge; no shutter. _Borrow:_ the scanner never asks for a tap. https://support.apple.com/en-us/102680

**Directions.**

**2A — Queue under the viewfinder.** _Pitch:_ the review is a second screen for a list the scanner already holds; show the staged rows here and commit here. _Regions:_ ScreenHeader · camera (~45 % height; reticle, torch, "Enter number instead" as an overlay button) · **staged cells** newest first (`GroupedRow`: name or warn "Name this product" · location `Chip` · "~7d" · tick); tapping an unknown row opens `TextPrompt`, so naming happens at the scan · footer **Add N to pantry** (primary) · **Review** (secondary; the primary disables with the review's own hint while a row needs attention). Empty: full-height camera, today's copy. Denied card unchanged. _Cost:_ clean haul = 1 tap (was 2); unknown named in 1 tap + typing, no modal. _Trade-off:_ two commit surfaces must share `BasketReview`'s commit (extract it); the camera loses height on small phones; D3 holds — the queue is the review.

**2B — Set the shelf first.** _Pitch:_ review-time location edits exist because the heuristic guesses per item; when one bag goes to one shelf, say so once. _Regions:_ ScreenHeader · camera with an **overlay SegmentedControl**: **Auto · Fridge · Pantry · Freezer** (>4 locations → a Chip opening `LocationPickerModal`); the mode stamps every following scan (Sortly, Barcode Buddy) · scan bar reads "6 staged · to Freezer" while set. Other states unchanged. _Cost:_ 1 tap per shelf change, 0 per item; single-shelf hauls need no review edits. _Trade-off:_ a forgotten mode misfiles a batch — Auto is the default, the count names the mode, review chips remain.

**2C — Result card, camera stays live.** _Pitch:_ replace haptic-plus-count with a card carrying the fact worth checking. _Regions:_ ScreenHeader · full camera · per scan a **card slides up** over the bottom third for ~2.5 s (Yuka): photo tile · name · "Fridge · ~7 days" · **Change** chip · ×; unknown → "Unknown barcode" with an inline **Name it** field; duplicate → the card says so; error → card with Add by name · scan bar under the camera. _Cost:_ 0 taps per known product; shelf change 2 taps now instead of in review; unknown named now. _Trade-off:_ a card over the reticle fights framing on small screens; more motion on a one-handed screen; VoiceOver keeps today's announcement.

## 3. Receipt / photo capture — `src/app/capture/receipt.tsx` (+ `ReceiptCapture.tsx`, `useParseReceipt.ts`, `quotaDisplay.ts`)

**Today.** ScreenHeader "Snap groceries or receipt" → viewfinder with an overlay **Receipt | Groceries** control, corner glyphs **Photos** / **PDF**, shutter → one meter line (month or day, amber/red as it binds) → **preview** (image · hint · privacy line · **Scan receipt** · Retake/Cancel) → **analyzing** (skeleton rows · **Hide** · "continues in the background") → the parse stages into the basket and opens the review; zero-items, quota upsell, daily cap, permission and retryable errors each keep Retake · Choose another · Try this photo again with an honest cost note. **Cost:** Snap row (1) → shutter (2) → Scan (3) → review → Add N (4); the 5–15 s wait holds the screen.

**Apps.**
- **Expensify SmartScan** — camera first; gallery bottom-left, shutter bottom-right; **Rapid Fire** shoots a stack of receipts; details fill in afterwards and you carry on. _Borrow:_ shoot-and-go with processing shown elsewhere; several receipts in one visit. https://help.expensify.com/articles/expensify-classic/expenses/Add-an-expense · https://www.androidpolice.com/2014/12/31/expensify-adds-beta-camera-features-rapid-fire-mode-add-from-gallery-and-led-flash-support/
- **Dext** — **Single / Multiple / Combine** modes at the bottom of the camera; Combine stitches a long receipt across up to 50 shots into one item; a **Processing** section tops the inbox while extraction runs. _Borrow:_ Combine for long receipts; processing as a section, not a held screen. https://help.dext.com/en/articles/105670-how-to-scan-and-upload-documents-in-the-dext-mobile-app
- **Apple Notes scanner** — Auto capture on edge detection; manual shutter; **Keep Scan / Retake**; add pages; Save with a count. _Borrow:_ a count on the commit button; two verbs on a preview. (Edge detection is not in `expo-camera`, so auto-capture is out.) https://support.apple.com/en-us/108963
- **Fetch** — frame squarely, shoot, then **slide the camera icon into the circle to submit**; green checks for store/date/total; X to retake; long receipts = several photos. _Borrow:_ a cheap deliberate gesture instead of a third screen; more photos of one receipt. https://help.fetch.com/hc/en-us/articles/115015779467-How-to-Snap-Receipts · https://help.fetch.com/hc/en-us/articles/115015804947-What-Info-is-Needed-on-a-Receipt
- **Wave** — long receipts captured in sections; bulk-upload up to 10; mark as reviewed later. _Borrow:_ confirms multi-section. https://support.waveapps.com/hc/en-us/articles/360059848112-Scan-and-upload-your-receipts

**Directions.**

**3A — Long receipt as parts.** _Pitch:_ a supermarket receipt does not fit one frame; the spec calls multi-shot "a v2". _Regions:_ viewfinder as today · after the shutter the frame **shrinks to a thumbnail strip** ("Part 1") and the camera stays live with an **Add next part** hint · **Scan 2 parts** replaces the right corner glyph once a part exists (Notes' count) · preview = swipeable parts with Retake each · other states and the meter unchanged. _Cost:_ +1 tap per part; one Scan, one charge. _Trade-off:_ the route takes one image — the honest build accepts up to 3 in one call (server change, escalation); client-side stitching under the ≤1600 px downscale loses legibility.

**3B — The shutter is the gate.** _Pitch:_ for a camera shot the preview repeats the viewfinder; keep the deliberate gesture as the shutter plus a short undo. _Regions:_ viewfinder, mode, meter and corner glyphs as today · shutter → the frame freezes for **2.5 s** as a chip "Sending… **Undo**" (Fetch's slide reduced to a tap-to-cancel; nothing leaves the phone before the window closes) · camera returns live; further shots queue as chips **Reading… / 7 items / Couldn't read · Retry** (Rapid Fire) · privacy line becomes a caption under the meter · library/PDF picks **keep the preview** (the mis-pick is D3's case) · quota/cap/permission unchanged. _Cost:_ Snap (1) → shutter (2) → review → Add (3); a second receipt is one more tap. _Trade-off:_ D3 says "after a preview"; the undo window is a preview in time — escalate in the PR; a pocket shutter is bounded by the window and the focus-unmount.

**3C — Reading happens in the basket.** _Pitch:_ the analyzing screen is dead time; the parse already outlives the screen, so let the wait live where the result lands. _Regions:_ viewfinder · preview with **Scan receipt** as today · on Scan: back to the **live viewfinder** with a "Reading… lands in your basket" toast · the Add tab's basket bar and badge read "Reading receipt… · 2 staged" · the review shows a **Reading… section** of skeleton cells above the rows (Dext's Processing) that fills in place · zero items → toast with **Retake**; retryable error → toast with **Try again** reopening the preview; quota/cap keep their full states. _Cost:_ same four taps, no held screen; a second receipt starts at once. _Trade-off:_ toast errors can be missed (mitigation: the Reading section becomes an error cell with the same buttons); `BasketContext` gains a pending-parse count.

## 4. Capture review — `src/app/capture-review.tsx` (+ `BasketReview.tsx`, `CaptureReviewList.tsx`, `CaptureEditor.tsx`)

**Today.** ScreenHeader "Review items" → header ("N items staged" · **Clear**; **Put everything in…** · **N of M** bulk tick) → `GroupedRow` cells: checkbox · name (warn "Name this product") · location `Chip` → picker · "expires Sep 11 · 7d" · category · caption (needs a name / doesn't look like a product name / we weren't sure) · chevron → `CaptureEditor` pageSheet → **N rows need attention · Show** → **Add N items to pantry** (disabled with a spoken reason). Empty: glyph + one sentence. **Cost:** clean = 1 tap; a location fix = 2; bulk location = 2 but ignores the ticks; a name fix = open + type + dismiss.

**Apps.**
- **Apple Mail** — Select mode; tap rows or **swipe down through the checkboxes**; Select All; **actions in a bottom bar** on the selection. _Borrow:_ drag-to-tick and a selection-scoped bar. https://support.apple.com/en-us/102428
- **Gmail (iOS)** — tap the avatar to start selecting; a **Select all** box appears; actions act on the selection. _Borrow:_ selection starts from the row's leading glyph, no mode switch. https://support.google.com/mail/answer/7401?co=GENIE.Platform%3DiOS
- **Fetch corrections** — a processed receipt lists items; **tap one to correct it**; **Add Item** → scan its barcode or Find Product for a missed line. _Borrow:_ fix and add-missing inside the review, the barcode as the precise fix. https://help.fetch.com/hc/en-us/articles/360036972413-How-to-Correct-Receipts-and-Get-Missing-Points
- **MyFitnessPal Meal Scan** — detected foods are confirmed; swipe through alternatives for a wrong guess; add extras via search; log all at once. _Borrow:_ alternatives on a low-confidence row (the contract still returns `candidates`). https://support.myfitnesspal.com/hc/en-us/articles/360045761612-Meal-Scan-FAQ
- **Splitwise Pro / Plates / splitty** — a scan detects items to assign; Plates drags items onto plates; splitty starts everything assigned and you tap to remove. _Borrow:_ drag onto a target; start assigned, correct by exception — the shape the confidence gate already has. https://www.splitwise.com/pro · https://splittyapp.com/learn/best-bill-splitting-apps/
- **Apple Reminders (Groceries)** — sections by category; drag to another section; remembered. _Borrow:_ sections as the primary structure. https://support.apple.com/en-us/105086

**Directions.**

**4A — Swipe-through ticks and a selection bar.** _Pitch:_ "Put everything in…" acts on all rows while the ticks say which rows matter; make the ticks the selection. _Regions:_ ScreenHeader · header: "N of M" only (Clear moves to an `OverflowMenu`) · cells as today with a **drag down the checkbox column** ticking a run (Mail) · when the ticked set differs from all, a **selection bar** above the CTA: **Put N in… · Remove N** · attention line and CTA as today. _Cost:_ untick 6 = one drag; move 8 rows = drag + 2 taps (was 16). _Trade-off:_ a pan over a FlatList needs gesture-handler care and a VoiceOver route (the bulk tick stays); include and select must be one meaning — ticked rows are what the bar acts on and what Add commits.

**4B — Grouped by shelf.** _Pitch:_ the reviewer's real question is "is this going to the right shelf"; answer it by reading. _Regions:_ ScreenHeader · summary · **sections per location** ("Fridge · 6", "Pantry · 4") with a per-section **all to…** (Reminders) · rows keep receipt order within a section; the location chip goes (the section says it) · a row moves by **drag** to another section (the drag P3 built for zones, #180) or via the editor · a we-weren't-sure row adds a **Try: “Heavy cream”** chip when `candidates` has one (MFP) · attention line and CTA as today. One location → no headers. _Cost:_ verifying shelves = 0 taps; a move = 1 drag; a section = 2 taps. _Trade-off:_ drag inside a sectioned FlatList is the heaviest build here; receipt order is split across shelves, so checking against paper is harder — the editor's raw-text meta remains.

**4C — Fix in place.** _Pitch:_ every attention reason is a name problem; a pageSheet is the wrong tool for a one-word fix. _Regions:_ header as today · tapping a **needs-a-name** row opens `TextPrompt` inline (validated by `rowNameInvalid`) · a **we-weren't-sure** caption becomes chips **Keep · Find in catalog** (the type-ahead as a sheet; relinking restores the estimate) · a last cell **Add something the scan missed** → search or scan (Fetch's Add Item) · chevron/editor stays for notes and category · attention line and CTA unchanged. _Cost:_ naming = 1 tap + typing, no modal; a missed line = 1 tap + search; a relink = 2 taps. _Trade-off:_ a keyboard in a FlatList needs scroll-to-focused handling; "Find in catalog" must reuse `SearchCapture`'s rows, not a fourth list.

## Where to bet

1. **2A Queue under the viewfinder** — the scanning haul is the most repeated capture; two screens become one and the unknown-barcode fix moves to the moment of the scan; D3 holds because the queue is the review, and the cells are `CaptureReviewList`'s.
2. **4B Grouped by shelf** — the review's real question becomes something read rather than tapped, and the drag exists since #180. Pair with 2B so "everything to Freezer" is said once, upstream.

Cheapest third: **3C** — no new gesture, no ADR strain, and it removes the only held wait in the app.
